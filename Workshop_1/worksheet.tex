\chapter*{Part 1 of the System Analysis Project}

\section*{1. Competition Overview}

The Kaggle competition \textit{“Titanic: Machine Learning from Disaster”} provides a structured dataset containing passenger information and a binary target variable indicating survival (1) or non-survival (0). The challenge consists of predicting this outcome using the available attributes.

Although commonly used for predictive modeling, in this workshop the dataset is treated as a \textbf{closed system} whose components, interactions, and constraints can be analyzed from a systems engineering perspective. All observations in this document are based exclusively on the variables and information provided directly by Kaggle.

\subsection*{Dataset Structure}

The dataset is composed of:

\begin{itemize}
    \item \texttt{train.csv}: Passenger attributes and survival labels.
    \item \texttt{test.csv}: Passenger attributes without labels.
    \item \texttt{gender\_submission.csv}: Example submission file.
\end{itemize}

\noindent
\textbf{Variables included in the dataset:}
\begin{itemize}
    \item \textbf{PassengerId}: Numerical identifier.
    \item \textbf{Pclass}: Ticket class (1, 2, or 3).
    \item \textbf{Name}: Full name (contains titles such as Mr., Mrs., Miss, etc.).
    \item \textbf{Sex}: Male or female.
    \item \textbf{Age}: Age in years (contains missing values).
    \item \textbf{SibSp}: Number of siblings or spouses aboard.
    \item \textbf{Parch}: Number of parents or children aboard.
    \item \textbf{Ticket}: Ticket code.
    \item \textbf{Fare}: Ticket fare.
    \item \textbf{Cabin}: Cabin identifier (mostly missing).
    \item \textbf{Embarked}: Port of embarkation (C, Q, or S).
\end{itemize}

\noindent
\textbf{Target Variable:} Survived (0 or 1).  
\textbf{Evaluation Metric:} Accuracy on Kaggle’s hidden test labels.  
\textbf{System Constraints:} Missing data, categorical encoding, and strict two-column submission format.

\section*{2. System Analysis Report}

\subsection*{Systemic Analysis}

From a systems engineering perspective, the Kaggle Titanic dataset models a logical system where each passenger instance represents a unit characterized by multiple attributes. The system’s purpose is to map these attributes to a binary output (\texttt{Survived}), forming an interpretable input–output structure.

\subsubsection*{System Elements}

\begin{itemize}
    \item \textbf{Inputs:}  
    Passenger demographic, social, and ticket-related attributes:
    \begin{itemize}
        \item Sex, Age
        \item Pclass
        \item SibSp, Parch
        \item Fare, Ticket
        \item Cabin (when available)
        \item Embarked
        \item Name (derivable titles)
    \end{itemize}

    \item \textbf{Processes (Dataset Interpretation):}
    These are transformations or interactions observable strictly from the data:
    \begin{itemize}
        \item Group structure encoded by SibSp + Parch
        \item Socioeconomic stratification encoded by Pclass and Fare
        \item Implicit categorization from titles in Name
        \item Embarked distribution patterns
    \end{itemize}

    \item \textbf{Output:}
    \begin{itemize}
        \item Survived (1) or Did Not Survive (0)
    \end{itemize}

    \item \textbf{Constraints within the Dataset System:}
    \begin{itemize}
        \item Missing values in Age and Cabin
        \item Skewed distribution of Cabin availability
        \item Categorical variables requiring interpretation
        \item Limited and fixed variable set
    \end{itemize}

\end{itemize}

\subsection*{Relationships Between Elements}

The dataset implies interactions between variables that shape the system behavior:

\begin{itemize}
    \item \textbf{Pclass ↔ Fare:} Higher classes generally correspond to higher fares.
    \item \textbf{Sex ↔ Survived:} The dataset shows different survival rates across genders.
    \item \textbf{Age ↔ Survived:} Younger passengers show different patterns than older ones.
    \item \textbf{SibSp + Parch ↔ Grouping Effects:} Larger family groups exhibit distinct survival patterns.
    \item \textbf{Embarked ↔ Fare \& Pclass:} Different ports show different fare distributions and class compositions.
\end{itemize}

These relationships reflect the internal structure of the dataset itself, without inferring external historical dynamics.

\subsection*{Complexity \& Sensitivity}

The dataset system exhibits complexity due to interactions and missing data.

\textbf{Complexity Sources:}
\begin{itemize}
    \item \textbf{Nonlinear relationships:}  
    Variables such as Sex, Age, and Pclass interact in non-additive ways.
    \item \textbf{Missingness:}  
    Age and Cabin introduce uncertainty and require imputation or exclusion.
    \item \textbf{Multiple categorical levels:}  
    Embarked, Pclass, and Name-derived titles increase structural complexity.
\end{itemize}

\textbf{Sensitivity:}  
Small changes in key variables alter system outcomes significantly:
\begin{itemize}
    \item Minor modifications to Age influence categorical grouping.
    \item Changing Sex produces large shifts in survival likelihood in the dataset.
    \item Removing Pclass reduces the dataset's predictive structure.
    \item Family variables (SibSp, Parch) alter patterns in subtle but noticeable ways.
\end{itemize}

All sensitivity observations come directly from variable–target relationships present in the Kaggle dataset.

\subsection*{Chaos and Randomness (Dataset Interpretation Only)}

Although the dataset is structured, certain patterns behave unpredictably from a purely statistical standpoint:

\begin{itemize}
    \item \textbf{Outliers:}  
    High Fare passengers found in lower classes or vice versa.
    \item \textbf{Inconsistent patterns:}  
    Some individuals with similar profiles have opposite survival outcomes.
    \item \textbf{Hidden structure:}  
    Missing cabins, ambiguous ticket codes, and name titles create irregular patterns.
    \item \textbf{Small variations producing large outcome shifts:}  
    Very similar passengers may differ in the target variable.
\end{itemize}

These behaviors are considered chaotic only within the context of the dataset’s statistical structure.

\subsection*{Conclusions}

The Kaggle Titanic dataset represents a closed, attribute–based system where a binary output (Survived) emerges from the interaction of demographic, social, and ticket-related features. Using only the information provided in the dataset, we can identify patterns, dependencies, and sensitivities that characterize the behavior of this system. No external information is required nor assumed.

\subsection*{Inputs}
These represent the raw elements that feed the system. The system is composed of demographic, social, and ticket-related attributes.

\begin{itemize}
    \item \textbf{Data Sources:} Files \texttt{train.csv} and \texttt{test.csv}.
    \item \textbf{Variables:} Conceptually grouped as follows:
    \begin{itemize}
        \item \textbf{Demographic:} Sex, Age, Name.
        \item \textbf{Socioeconomic:} Pclass (Class), Fare.
        \item \textbf{Family:} SibSp (Siblings/Spouses), Parch (Parents/Children).
        \item \textbf{Logistic:} Ticket, Cabin, Embarked.
    \end{itemize}

\subsection*{The System (Internal Logic and Transformations)}
The ``Process'' in this context is not an external Machine Learning algorithm, but the intrinsic interactions observable strictly from the data.

\begin{itemize}
    \item \textbf{Interactions:} Variables do not act alone, but interact through specific mechanisms:
    \begin{itemize}
        \item \textit{Stratification:} The relationship between Pclass and Fare defines status.
        \item \textit{Grouping:} SibSp and Parch create a family group structure.
        \item \textit{Derivation:} The Name attribute contains implicit titles (Mr., Mrs.) that generate categories.
    \end{itemize}
    
    \item \textbf{Constraints:} The system has internal limitations such as missing values in Age and Cabin that introduce uncertainty.
    
    \item \textbf{Sensitivity:} Small changes in key variables (such as Sex or minor modifications in Age) drastically alter the system's outcome.
\end{itemize}

\subsection*{Output}
The system's final purpose is to map the processed inputs to a single binary state.

\begin{itemize}
    \item \textbf{Variable:} Survived (0 = Did Not Survive, 1 = Survived).
    \item \textbf{Nature:} It is an emergent result of the interaction of the aforementioned attributes.
\end{itemize}
